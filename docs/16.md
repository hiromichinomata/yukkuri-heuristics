# 第16章 遺伝的アルゴリズムと母集団探索

> **到達目標（青色帯 1600〜1999）**: 配置・順序問題を **染色体（順列・ビット列など）** で表し、交叉・突然変異・選択で解を進化させられる。母集団サイズと多様性のトレードオフを説明できる。

---

## 16.1 交叉（Crossover）と突然変異（Mutation）

**霊夢**: 焼きなましは「1 解をじわじわ変える」って聞いたけど、GA って別物なの？

**魔理沙**: **遺伝的アルゴリズム（GA）** は **母集団（複数の解）** を同時に持ち、**交叉** で親の良い部分を混ぜ、**突然変異** で多様性を足す。配置の **並べ順** のように、解が **順列** なら **順序交叉（OX）** が定番だ。

| 操作 | 役割 | 第16章コード |
|------|------|-------------|
| 交叉 | 親2体から子を作る | `order_crossover` |
| 突然変異 | 局所をランダムに崩す | `mutate`（2 位置スワップ） |
| 評価 | 染色体→スコア | `evaluate` |

```python
# python/ch16/ga_placement.py — 順序交叉の骨格

```

**霊夢**: なんで順列なの？

**魔理沙**: 幅つきアイテムを **左から詰める順序** が染色体だと、同じ集合でも並べ方で入る幅が変わる。AHC の配置・パッキングでも「**何を先に置くか**」を順列で持つパターンが多い。

## 16.2 選択（Selection）と多様性維持

**霊夢**: いつも一番強い個体だけ残すと、似た解ばかりにならない？

**魔理沙**: その通り。**トーナメント選択** は K 体をランダムに取り、その中で最良を親にする——常に最強だけ選ぶより **多様性** が残る。

```python
TOURNAMENT_K = 3

def tournament_select(population, fitness, rng):
    # K 体のうち fitness 最大を返す
```

**霊夢**: エリート保存って？

**魔理沙**: 各世代で **今の最良個体をそのまま次世代にコピー** する。第16章は `elite = max(...)` を `next_pop` の先頭に入れている。これがないと、たまたま交叉で最良が消えることがある。

| 手法 | 効果 |
|------|------|
| トーナメント | 選択圧を K で調整 |
| エリート保存 | 最良解の喪失を防ぐ |
| 突然変異率 | 多様性の注入（高すぎると破壊的） |

```python
elite = max(range(POP_SIZE), key=lambda i: fitness[i])
next_pop.append(list(population[elite]))
```

## 16.3 問題に合った染色体表現

**霊夢**: 染色体ってビット列だけじゃないの？

**魔理沙**: **問題の構造に合わせる** のが鉄則だ。

| 問題の性質 | 染色体の例 |
|-----------|-----------|
| 順序・スケジュール | 順列（permutation） |
| 入れる/入れない | ビット列 |
| 連続値（座標） | 実数ベクトル + 丸め |
| 木・グラフ | 親子リスト + 修復関数 |

第16章は **1 次元ナップサック風配置**: `order = [0,1,...,n-1]` の順列で左から詰め、はみ出す幅はスキップする。

```python
def evaluate(problem, order):
    pos = 0
    placed_width = 0
    for idx in order:
        w = problem.widths[idx]
        if pos + w > problem.capacity:
            continue
        pos += w
        placed_width += w
    return placed_width, placement
```

**霊夢**: 評価が遅いと GA も遅い？

**魔理沙**: そう。本番では **キャッシュ** や **差分評価**、世代数・母集団の削減とセットで考える。青色帯ではまず **表現が自然か** を最優先に設計する。

### GA と SA・貪欲の使い分け

| 手法 | 強み | 弱み |
|------|------|------|
| 貪欲 | 速い・実装簡単 | 順序の良さを見逃す |
| SA（第8章） | 1 解を深く改善 | 初期解に依存 |
| GA | 順列・組合せの **広い探索** | パラメータと世代コスト |

第16章の 1D 配置では、幅降順貪欲が強いことも多い。GA は **「順序の良い個体」が交叉で混ざる** ことで、貪欲単体では届かない順序を見つける用途向きだ。

```python
# 突然変異 — 2 点スワップ（順列を保つ）
def mutate(order, rng):
    if rng.random() >= MUTATION_RATE:
        return
    i, j = rng.sample(range(len(order)), 2)
    order[i], order[j] = order[j], order[i]
```

```go
func mutate(order []int, rng *rand.Rand) {
    if rng.Float64() >= mutationRate {
        return
    }
    i, j := rng.Intn(len(order)), rng.Intn(len(order))
    order[i], order[j] = order[j], order[i]
}
```

**霊夢**: stderr の `ga gen=` は何世代目？

**魔理沙**: 50 世代ごとの **best-so-far の placed_width**。本番では **残り時間で世代上限** を決め、提出は常に歴代最高個体から復元した配置にする。

## 16.4 ハンズオン: 配置問題に GA を適用する

**霊夢**: リポジトリのどこを動かせばいいの？

**魔理沙**: `python/ch16/ga_placement.py` と `go/ch16/ga_placement.go`。入力は `data/ch16/sample.txt`。

```
100          # capacity
12           # n
8 5 12 ...   # widths
```

### Step 1: 実行

```bash
python python/ch16/ga_placement.py < data/ch16/sample.txt
go run go/ch16/ga_placement.go < data/ch16/sample.txt
```

stderr に `ga gen=0 best=92` のように世代ログ、stdout に配置 `(index, position, width)` が出る。

### Step 2: パラメータ改変

```python
POP_SIZE = 20      # 小さく → 収束速いが多様性低下
POP_SIZE = 80
MUTATION_RATE = 0.05
MUTATION_RATE = 0.3
GENERATIONS = 50
```

各設定で **最終 `placed_width`** を表にする（16.5 演習）。

### Step 3: 貪欲との比較

幅の大きい順に詰める貪欲を別途書き、GA の `best_fit` と比べる。順序問題では **GA が貪欲を上回る** こともあるが、必ずしも GA が勝つわけではない——**時間対効果** で SA / ビームと比較するのが青色の作法だ。

### Step 4: コンテスト形式

- 残り時間で `GENERATIONS` をループ上限にする
- stderr に **best-so-far** のみ記録し、提出は常に歴代最高配置

### Step 5: Go 側の対応表

| Python | Go |
|--------|-----|
| `POP_SIZE` | `popSize` |
| `order_crossover` | `orderCrossover` |
| `ga()` ループ | `ga()` + `randPerm` |
| stderr `ga gen=` | `fmt.Fprintf(os.Stderr, ...)` |

入出力形式は完全に同一。AtCoder では **提出言語を1つ決め**、ローカルで両方動かしてデバッグするのが本書の想定だ（`docs/00.md`）。
