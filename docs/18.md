## 18.1 シードを変えた multi-start SA

**霊夢**: 第9章は seed=42 固定だったけど、1 回じゃ運が悪いこともある？


```go

// 各 seed で saRun → スコア最大の結果を採る
```

| 単一 SA | multi-start |
|---------|-------------|
| 1 つの谷に張り付き | 複数の谷を試す |
| パラメータ1組 | シード＝暗黙の多様性 |

**霊夢**: 4 本回すなら、時間も4倍かかる？

**魔理沙**: 提出コードでは **制限時間を4つに分けて順番に回す**。1本あたりは短くなるが、「1本を長く」と「4本を短く」のどちらが強いかは問題次第だ（演習2）。

```python
# python/ch18/multi_start_sa.py — 提出用（既定）: 合計時間をシード数で等分して逐次に回す
def multi_start_sequential(problem, seeds, total_sec):
    per_seed = total_sec / len(seeds)
    results = [sa_run(problem, seed, per_seed) for seed in seeds]
    best_types, best_score, _ = max(results, key=lambda r: r[1])
    return best_types, best_score
```

## 18.2 ローカルでの並列実行（Python: multiprocessing, Go: goroutine）と提出時の注意

**霊夢**: 並列にすれば4本同時に回せるんじゃない？

**魔理沙**: ローカルではそうだ。`--parallel` を付けると各シードを同時に回す。Python は GIL があるので **`ProcessPoolExecutor` で別プロセス** に、Go は **goroutine + `sync.WaitGroup`** だ。

```python
# python/ch18/multi_start_sa.py — ローカル実験用
def multi_start_parallel(problem, seeds, per_seed_sec):
    with ProcessPoolExecutor(max_workers=len(seeds)) as ex:
        results = list(ex.map(_worker, [(problem, seed, per_seed_sec) for seed in seeds]))
    best_types, best_score, _ = max(results, key=lambda r: r[1])
    return best_types, best_score
```

```go
// go/ch18/multi_start_sa.go — ローカル実験用
var wg sync.WaitGroup
for i, seed := range seeds {
	wg.Add(1)
	go func(i int, seed int64) {
		defer wg.Done()
		results[i] = saRun(problem, seed, perSeed)
	}(i, seed)
}
wg.Wait()
```

| 言語 | 並列単位 | 注意 |
|------|---------|------|
| Python | `multiprocessing` | `ProblemInput` は picklable であること。プロセス起動に時間がかかる |
| Go | goroutine | 共有メモリは読み取り専用 `problem` が安全 |

**霊夢**: じゃあ提出コードも並列にすれば、4倍探索できる？

**魔理沙**: そこは **期待するな**。ジャッジで複数コアが使える保証はないし、実行時間の制限は壁時計で見られると思っておけ。並列にしても速くならない上に、Python ではプロセス起動のコストだけで持っていかれて **TLE** になりかねない。実際、下のハンズオンでも Python の並列版は 1 シード 0.4 秒なのに壁時計は 0.5 秒かかっている。

| 用途 | おすすめ |
|------|---------|
| **提出コード** | 制限時間を **逐次** に分割して multi-start（既定の動作） |
| **ローカル実験** | `--parallel` でシードやテストケースを **並列** に回し、比較を速くする |

## 18.3 最良解のマージ戦略

**霊夢**: 4 本とも解が返ってきたら？

**魔理沙**: 第18章は **スコア最大の解を1つ選ぶ** だけ——シンプルで堅い。

```python
# python/ch18/multi_start_sa.py
best_types, best_score, _ = max(results, key=lambda r: r[1])
```

| マージ戦略 | 向き |
|-----------|------|
| max score | 定番・実装が軽い |
| スコア上位 k を SA で再融合 | さらに伸ばす（時間要） |
| 操作列の交叉 | 研究寄り・チューニング難 |

**霊夢**: best-so-far は各シードの中でも必要？

**魔理沙**: 当然。`sa_run` 内でも **受理中の current** と **歴代最高 best** を分ける（第9章・第11章と同じ）。マージは **シード間の best** の比較だ。

## 18.4 再現性と乱数管理

**霊夢**: シードを変えると再現できなくなる？

**魔理沙**: **シードを固定** すれば各ランの乱数列は決まる。`Random(42)` と `Random(43)` は独立系列だ。ただし時間で打ち切る SA は、マシンの速さで回るステップ数が変わるので、結果まで完全に同じにはならない。

```python
# python/ch18/multi_start_sa.py
rng = random.Random(seed)  # シードごとに別の RNG を作る
```

| ルール | 理由 |
|--------|------|
| シードごとに別 RNG | 探索の多様性 |
| ログに seed を書く | デバッグ・再実行 |
| グローバル RNG を共有しない | 再現不能・競合 |

Go では `rand.New(rand.NewSource(seed))` をシードごとに作る。

**霊夢**: 黄色帯で出てくる MCTS（第20章）とも組み合わせられる？

**魔理沙**: 同じ「時間を分けて別乱数で走らせ、max で返す」骨格は MCTS にも載る。並列 MCTS（ルート並列・葉並列）は黄色〜橙の領域だ。

## 18.5 ハンズオン: 4 シードの SA で最良解を更新する

**霊夢**: 入力は第16章と同じ？

**魔理沙**: Intro HC 形式の `data/ch18/sample.txt`。スコア計算と差分更新は第9章と同一だ。

### Step 1: 実行（提出用 = 逐次）

```bash
python python/ch18/multi_start_sa.py < data/ch18/sample.txt
go run go/ch18/multi_start_sa.go < data/ch18/sample.txt
```

（時間・step 数・途中のスコアはマシン速度で変わる。Go 版は乱数列が違い、1 秒あたりのステップ数も桁違いに多い。）

### Step 2: ローカル実験用の並列

```bash
python python/ch18/multi_start_sa.py --parallel < data/ch18/sample.txt
go run go/ch18/multi_start_sa.go -parallel < data/ch18/sample.txt
```

```

...
mode=parallel seeds=4 merged best score=1079507 wall=0.51s
```

（時間・step 数・途中のスコアはマシン速度で変わる。）

**霊夢**: 壁時計は 1.6 秒 → 0.5 秒。でも steps が減ってる？

**魔理沙**: 4 プロセスが CPU を取り合うからだ。しかも 1 シード 0.4 秒なのに壁時計は 0.51 秒——**プロセス起動のコスト** が見えている。ローカルでは比較が速くなって便利だが、提出には向かない理由がこれだ。

### Step 3: シード数と時間

```bash
python python/ch18/multi_start_sa.py --seeds 8 < data/ch18/sample.txt   # 8 シード × 各 0.2 秒
python python/ch18/multi_start_sa.py --seeds 1 < data/ch18/sample.txt   # 1 シード × 1.6 秒
python python/ch18/multi_start_sa.py --time 1.8 < data/ch18/sample.txt  # 合計時間を変える
```

本番 2 秒なら、入出力と余裕を残して合計 1.6〜1.8 秒程度にする。

### Step 4: 第11章パイプラインとの合成

```
[貪欲 or ランダム] → [multi-start SA（逐次）] → best 提出
```

第11章の **construct / improve 分割** で、improve 段を `multi_start_sa` に置き換えるイメージだ。
