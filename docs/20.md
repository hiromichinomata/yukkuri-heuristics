## 20.1 シードを変えた multi-start SA

**霊夢**: 第8章は seed=42 固定だったけど、1 回じゃ運が悪いこともある？

**魔理沙**: そう。**multi-start** は初期解と乱数列を変えて SA を何度も走らせ、**最高スコアだけ採用** する。局所最適の「谷」が違うから、1 本より伸びやすい。

```python
# python/ch20/parallel_sa.py
seeds = [42, 43, 44, 45]

def sa_run(problem, seed, time_limit_sec):
    rng = random.Random(seed)
    state = ScheduleState([rng.randint(1, 26) for _ in range(problem.days)])
    # ... 通常の SA ループ ...
    return best_types, best_score
```

```go
// go/ch20/parallel_sa.go
seeds := []int{42, 43, 44, 45}
// 各 seed で saRun → 最大スコアを merge
```

| 単一 SA | multi-start |
|---------|-------------|
| 1 つの谷に張り付き | 複数の谷を同時探索 |
| パラメータ1組 | シード＝暗黙の多様性 |

**霊夢**: 時間は4倍？

**魔理沙**: **並列** にすれば壁時計はほぼ1本分。第20章は **ワーカーごとに同じ `TIME_LIMIT_SEC`** を割り当て、終わったらマージする。

## 20.2 時間分割並列（Python: multiprocessing, Go: goroutine）

**霊夢**: Python の GIL って邪魔じゃない？

**魔理沙**: **CPU バウンドな SA ループ** は `ProcessPoolExecutor` で別プロセスに逃がす。I/O 待ちなら `ThreadPoolExecutor` だが、第20章は前者。

```python
from concurrent.futures import ProcessPoolExecutor, as_completed

with ProcessPoolExecutor(max_workers=NUM_WORKERS) as ex:
    futures = [
        ex.submit(_worker, (problem, seed, TIME_LIMIT_SEC))
        for seed in seeds
    ]
    for fut in as_completed(futures):
        results.append(fut.result())
```

サンドボックス等でプロセスが使えない環境では **順次 fallback** する:

```python
except Exception as exc:
    print(f"parallel fallback ({exc})", file=sys.stderr)
    for seed in seeds:
        results.append(sa_run(problem, seed, TIME_LIMIT_SEC))
```

**Go** は goroutine + `sync.WaitGroup` で同時に `saRun` し、チャネルまたはスライスに結果を集める。

```go
// go/ch20/parallel_sa.go — 概略
var wg sync.WaitGroup
results := make(chan RunResult, numWorkers)
for _, seed := range seeds {
    wg.Add(1)
    go func(s int) {
        defer wg.Done()
        types, score := saRun(problem, s, timeLimitSec)
        results <- RunResult{types, score, s}
    }(seed)
}
```

| 言語 | 並列単位 | 注意 |
|------|---------|------|
| Python | `multiprocessing` | `ProblemInput` は picklable であること |
| Go | goroutine | 共有メモリは読み取り専用 `problem` が安全 |

## 20.3 最良解のマージ戦略

**霊夢**: 4 本とも解が返ってきたら？

**魔理沙**: 第20章は **スコア最大の解を1つ選ぶ** だけ——シンプルで堅い。

```python
best_types, best_score = max(results, key=lambda x: x[1])
print(f"merged best score={best_score}", file=sys.stderr)
```

| マージ戦略 | 向き |
|-----------|------|
| max score | 定番・実装が軽い |
| スコア上位 k を SA で再融合 | さらに伸ばす（時間要） |
| 操作列の交叉 | 研究寄り・チューニング難 |

**霊夢**: best-so-far は各ワーカー内でも必要？

**魔理沙**: 当然。`sa_run` 内でも **受理中の current** と **歴代最高 best** を分ける（第8章・第10章と同じ）。マージは **ワーカー間の best** の比較だ。

## 20.4 再現性と乱数管理

**霊夢**: 並列にすると再現できなくなる？

**魔理沙**: **シードを固定** すれば各ワーカーは決定的。`Random(42)` と `Random(43)` は独立系列。

```python
rng = random.Random(seed)  # ワーカーごとに seed を変える
```

| ルール | 理由 |
|--------|------|
| ワーカーごとに別 seed | 探索の多様性 |
| 本番ログに seed を書く | デバッグ・再実行 |
| グローバル RNG を共有しない | 再現不能・競合 |

Go では `rand.New(rand.NewSource(int64(seed)))` をワーカーごとに作る。

**霊夢**: 第19章 MCTS とも組み合わせられる？

**魔理沙**: **並列 MCTS**（ルート並列・葉並列）も黄色〜橙の領域。第20章は **SA multi-start** が土台。同じ「時間を分けて別乱数で走らせ、max で返す」骨格は MCTS にも載る。

## 20.5 ハンズオン: 4 並列 SA で最良解を更新する

**霊夢**: 入力は第18章と同じ？

**魔理沙**: Intro HC 形式の `data/ch20/sample.txt`（`days` 小さめでも可）。`score_schedule` は第8章と同一。

### Step 1: 実行

```bash
python python/ch20/parallel_sa.py < data/ch20/sample.txt
go run go/ch20/parallel_sa.go < data/ch20/sample.txt
```

stderr 例（Python）:

```
worker seed=42 best=1078260 steps=87594
worker seed=43 best=1078260 steps=86082
...
merged best score=1078260
```

Go も同様に `worker seed=` と `merged best score=` を出力。

### Step 2: 並列数

```python
NUM_WORKERS = 2
seeds = [42, 43]
# または seeds = list(range(42, 50))  # 8 並列
```

**壁時計** と **各 worker の best** を表にする（20.6 演習）。

### Step 3: 時間配分

```python
TIME_LIMIT_SEC = 0.4   # ワーカーあたり
# 合計 ≒ 0.4s（並列） vs 0.4 * 4（逐次 fallback）
```

本番 2 秒なら「**4 ワーカー × 各 2 秒並列**」がよくある設定。

### Step 4: 第10章パイプラインとの合成

```
[貪欲 or ランダム] → [並列 multi-start SA] → best 提出
```

第10章の **construct / improve 分割** に、improve 段を `parallel_sa` に置き換えるイメージだ。
