## 20.1 UCB1 と探索 / 利用

**霊夢**: 貪欲はいつも一番良さそうな手を取るけど、MCTS は違うの？

**魔理沙**: **Monte Carlo Tree Search** は、試した回数の少ない手も試す。**UCB1** で「期待利得 + 探索ボーナス」を最大化する子を選ぶ。

\[
\text{UCB1}(i) = \frac{w_i}{n_i} + c \sqrt{\frac{\ln N}{n_i}}
\]

| 記号 | 意味（第20章） |
|------|----------------|
| \(w_i\) | 子ノードの累積勝利（`wins`） |
| \(n_i\) | 子の訪問数（`visits`） |
| \(N\) | 親の訪問数 |
| \(c\) | 探索定数（`EXPLORATION = 1.41`） |

```python
# python/ch20/mcts_toy.py
def ucb1(parent_visits: int, child: MCTSNode) -> float:
    if child.visits == 0:
        return float("inf")  # 未訪問を最優先
    return child.wins / child.visits + EXPLORATION * math.sqrt(
        math.log(parent_visits) / child.visits
    )
```

```go
// go/ch20/mcts_toy.go
func ucb1(parentVisits int, child *MCTSNode) float64 {
	if child.Visits == 0 {
		return math.Inf(1)
	}
	return child.Wins/float64(child.Visits) + exploration*math.Sqrt(math.Log(float64(parentVisits))/float64(child.Visits))
}
```

**霊夢**: `visits == 0` が inf なのは？

**魔理沙**: **各手を最低1回は試す** ため。探索不足で強い手だけに偏るのを防ぐ。

## 20.2 ゲーム木とシミュレーション

**霊夢**: 木って全部先読みするの？

**魔理沙**: **全部は無理**。4 フェーズで **必要な枝だけ** 伸ばす。

```
1. Selection   … ルートから UCB1 で葉へ
2. Expansion   … 未試行の手で子ノードを1つ追加
3. Simulation  … ランダム（または貪欲）で終局まで rollout
4. Backprop    … 経路上の visits / wins を更新
```

```python
# 骨格（実物は python/ch20/mcts_toy.py の mcts。終局ノードの判定などを省いている）
def mcts(root, adj, game, rng):
    for _ in range(ITERATIONS):
        node = root
        path = [node]
        # Selection: 子が全部展開済みなら UCB1 で降りる
        while not node.untried and node.children:
            node = best_child(node)
            path.append(node)
        # Expansion
        if node.untried:
            node = expand(node, adj, rng)
            path.append(node)
        # Simulation (rollout)
        winner = rollout(node.state, adj, game, rng)
        # Backpropagation
        for n in path:
            n.visits += 1
            # n の勝率は「n へ進む手を指した人」から見たもの（n で次に指す人の相手）
            if winner == 1 - n.state.player:
                n.wins += 1.0
```

Go 版の Backprop も同じ数え方だ。

```go
// go/ch20/mcts_toy.go — Backpropagation
for _, n := range path {
	n.Visits++
	// ノード n の勝率は「n へ進む手を指した人」（= n で次に指す人の相手）から見たもの
	if n.HasState && winner == 1-n.State.Player {
		n.Wins++
	}
}
```

**霊夢**: 第20章の「ゲーム」は？

**魔理沙**: **4 ノードの無向グラフ**（`data/ch20/sample.txt`）。`start=0`、ノード `3` に着いたプレイヤーが勝ち。ターンごとに MCTS で1手選び、最大 `MAX_TURNS` 手。

## 20.3 ヒューリスティック問題への MCTS 適用

**霊夢**: AHC はスコア最大化なのに、勝敗？

**魔理沙**: ヒューリスティックでも **ターン制・対戦型** なら MCTS が使える。単独最適化なら **rollout の終端スコア** を `wins` に足す形に変える。

| 問題型 | MCTS の状態 | rollout 終端 |
|--------|-------------|--------------|
| 対戦（Territory 等） | 盤面 + 手番 | 勝敗 / スコア差 |
| ターン制単独 | 操作列 + 残ターン | `score_schedule` 等 |
| 連続操作 | 部分解 | 貪欲で埋めて評価 |

第17章 Territory では「自分の手を選ぶ → 相手も動く」を木に載せられる。計算量が重いので **浅い深さ + 強い rollout ポリシー** が現実的だ。

**霊夢**: 第20章コードは対戦だけ？

**魔理沙**: 学習用に **勝敗がはっきりしたグラフ** にしている。応用時は `terminal_winner` を **スコア閾値** に差し替えればよい。

```python
# python/ch20/mcts_toy.py
def terminal_winner(state, game):
    if state.node == game.terminal:
        # state.player は「次に指す人」。終点に入ったのはその相手なので、相手の勝ち
        return 1 - state.player
    return None
```

**霊夢**: 勝ちを数えるとき「1 - 手番」なのはなぜ？

**魔理沙**: 二人対戦の MCTS でいちばん間違えやすい所だ。親ノードは子ノードの勝率を見て手を選ぶ——つまり子の勝率は **その手を指した人（親の手番）** から見た値でないといけない。子ノードに入っている `player` は「次に指す人」なので、その相手の勝ちを数える。逆にすると、**相手が喜ぶ手** を選んでしまう。

## 20.4 時間制限内での rollout 回数

**霊夢**: `ITERATIONS = 300` 固定？

**魔理沙**: 既定は **再現性のため** の固定回数だ。本番は **残り時間まで** 回す。`mcts_toy` も `--time-per-move 秒` を付けると時間で回す版になる。1 イテレーションのコストは **展開 + rollout 長** で決まる。

```python
# python/ch20/mcts_toy.py
def mcts(
    root: MCTSNode,
    adj: List[List[int]],
    game: GameInput,
    rng: random.Random,
    deadline: Optional[float] = None,
) -> int:
    done = 0
    while done < ITERATIONS if deadline is None else time.perf_counter() < deadline:
        done += 1
```

```bash
python python/ch20/mcts_toy.py --time-per-move 0.05 < data/ch20/sample.txt
go run go/ch20/mcts_toy.go --time-per-move 0.05 < data/ch20/sample.txt
```

stderr の `mcts iterations=...` が、その時間で回せた合計回数だ。固定回数（16 手 × 300 = 4800）と比べると、Python と Go の速度差もそのまま見える。時間で回すと回数が実行ごとに変わるので、**手列の再現性はなくなる**——デバッグ中は固定回数、提出は時間、と使い分ける。

| 調整ノブ | 効果 |
|---------|------|
| イテレーション数 ↑ | 手の評価が安定、時間↑ |
| rollout 深さ ↓ | 速いが評価がノイジー |
| `EXPLORATION` ↑ | 探索寄り（未試行の手を多く見る） |
| `EXPLORATION` ↓ | 利用寄り（高 win 率の手に集中） |

```python
# python/ch20/mcts_toy.py
EXPLORATION = 1.41  # √2 がよく使われる
ITERATIONS = 300  # --time-per-move を付けると、回数ではなく時間で回す
```

**霊夢**: 1 手だけ MCTS して選ぶ？

**魔理沙**: `play_game` は **毎ターン root を新規構築** し、`select_move` で訪問数最大の子を選ぶ（robust child）。

```python
# python/ch20/mcts_toy.py — select_move
return max(root.children, key=lambda m: root.children[m].visits)
```

Go 版は子を `map` で持つが、`map` の走査順は実行ごとにランダムだ。訪問数が同点のとき選ぶ子が変わってしまうので、子を作った順を `Order` に残し、その順で走査している（Python の dict は挿入順なので、これで同じ子を選ぶ）。

```python
# python/ch20/mcts_toy.py — 現状: ランダムな合法手で終局まで進める
def rollout(state: GameState, adj: List[List[int]], game: GameInput, rng: random.Random) -> int:
    cur = state
    for _ in range(game.nodes * 4):
        winner = terminal_winner(cur, game)
        if winner is not None:
            return winner
        moves = adj[cur.node]
        if not moves:
            return 1 - cur.player
        cur = apply_move(cur, rng.choice(moves))
    return 1 - cur.player
```

```python
# 改変例: 終点に隣接していれば必ずそこへ行く（1手読みの貪欲 rollout）
        moves = adj[cur.node]
```
