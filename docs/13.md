## 13.1 Union-Find（素集合データ構造）

**霊夢**: Union-Find って、グループ分けを高速にマージするやつ？

**魔理沙**: **素集合データ構造**だ。`find` で代表元、`unite` で集合を合体。**経路圧縮**と**ランク（またはサイズ）** でほぼ定数時間。

```python
# python/ch13/union_find.py
class UnionFind:
    def find(self, x: int) -> int:
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]  # 経路圧縮
            x = self.parent[x]
        return x

    def unite(self, a: int, b: int) -> bool:
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False
        # ランクで木の高さを抑える
        ...
        return True
```

```go
// go/ch13/union_find.go
func (uf *UnionFind) Find(x int) int {
    for uf.parent[x] != x {
        uf.parent[x] = uf.parent[uf.parent[x]]
        x = uf.parent[x]
    }
    return x
}
```

**霊夢**: `unite` が `False` のときは、もともと同じグループ？

**魔理沙**: そう。**辺を足しても連結成分数が減らない** ときはスキップできる。AHC010 系では「ループを作りすぎない」判定に使う。

### ベンチマーク（単体実行）

```bash
go run go/ch13/union_find.go
```

`n=5000`・`m=20000` の union 反復で、素朴再構築より **数倍〜十数倍** 速くなる（環境依存）。

## 13.2 セグメント木・Fenwick Tree によるスコア差分更新

**霊夢**: Fenwick は区間和を速くするツリー？

**魔理沙**: **Binary Indexed Tree** だ。一点更新・前缀和が `O(log n)`。セグメント木はより汎用だが、実装は Fenwick の方が短い。

```python
# python/ch13/fenwick.py
class Fenwick:
    def add(self, i: int, delta: int) -> None:
        i += 1
        while i <= self.n:
            self.bit[i] += delta
            i += i & -i

    def range_sum(self, l: int, r: int) -> int:
        if l == 0:
            return self.prefix(r)
        return self.prefix(r) - self.prefix(l - 1)
```

```go
// go/ch13/fenwick.go — 同様の add / prefix / range_sum
```

**霊夢**: 近傍でスコアが「区間の和の変化」だけなら、全配列をなめなくていいのね。

**魔理沙**: その設計が **差分更新可能な近傍** だ。毎回 `sum(arr[l:r+1])` すると `O(n)`、Fenwick なら `O(log n)`。

## 13.3 ヒープ・優先度キューによる貪欲高速化

**霊夢**: ヒープは第11章のダイクストラでも使ってたわね。

**魔理沙**: **最小コストを常に取り出す** 構造だ。用途は次の通り。

| 用途 | 例 |
|------|-----|
| ダイクストラ | `heapq` で `(距離, 頂点)` |
| 貪欲マッチング | コスト昇順の辺をキューから |
| ビームサーチ | `heapq.nsmallest`（第14章） |
| スケジューリング | 締切順のイベントキュー |

```python
import heapq
pq = [(0.0, start)]
d, u = heapq.heappop(pq)
heapq.heappush(pq, (nd, v))
```

**霊夢**: Go は `container/heap` を使うの？

**魔理沙**: 本番 Go では **heap パッケージ** が定番。第11章サンプルは頂点が小さいので配列ダイクストラでも足りるが、**V≥1000** なら heap に切り替えろ。

## 13.4 差分更新可能な近傍操作の設計

**霊夢**: 第12章の `before` / `after` も差分更新？

**魔理沙**: TSP の 2-opt では **4 辺だけ** 見ればよい。タブーでも `new_len = cur_len - before + after` としている。

| 問題 | 差分の単位 |
|------|-----------|
| TSP 2-opt | 削除2辺 + 追加2辺 |
| グリッド辺追加 | 連結成分数の変化（UF） |
| スコア配列 | Fenwick の `add` |

**霊夢**: 全再計算との比較は第13章の `loop_toy`？

**魔理沙**: `python/ch13/loop_toy.py` が **辺追加のたびに全 UF 再構築** vs **インクリメンタル UF** を比較する。
