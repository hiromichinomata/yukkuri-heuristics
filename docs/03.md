## 3.1 ストーリー・制約・スコア計算式・入力生成方法の読み方

**霊夢**: AHC の問題文、長くて読むのが億劫なの。

**魔理沙**: 最初から全部読まなくていい。**4か所だけ**先に拾えばいい。

| 読む場所 | 探すもの | 例（Intro HC 問題A） |
|---------|---------|---------------------|
| ストーリー | 何を最適化するか | 365日間のコンテスト日程 |
| 制約 | 入力サイズ・値の範囲 | D=365, 0≤s≤20000 |
| スコア計算式 | 出力→点数のルール | max(10^6 + S, 0) |
| 入力生成方法 | テストの作られ方 | c_i, s_{d,i} は一様ランダム |

**霊夢**: ストーリーは飾り？

**魔理沙**: 飾りじゃない。**何を出力すればいいか** がストーリーに埋まってる。「毎日1コンテスト、タイプ1〜26」——これが出力形式のヒントだ。

```text
# Intro HC 問題A — 読む順番チェックリスト
[ ] 出力形式: t_1, t_2, ..., t_D（各日1つのタイプ）
[ ] 目的: 最終満足度 S を最大化
[ ] スコア: max(10^6 + S, 0) × 50ケース合計
[ ] TL: 2 秒
[ ] 入力生成: 各パラメータ一様ランダム
```

**霊夢**: 入力生成方法って、競プロの問題文にあるの？

**魔理沙**: AHC では**だいたい書いてある**。これを読むと「極端なケース」を想像できる。例えば `c_i` が全部 0 なら減衰がない、全部 100 なら減衰がきつい——とかだ。

**霊夢**: スコア式は数式で書かれてることが多いの？

**魔理沙**: そう。LaTeX っぽい式を**そのままコードに落とす**練習をする。問題B では各日の満足度 v_d を出力する——つまり**スコア計算の中間結果**が出力になることもある。

- 値の範囲:

## 3.2 「まず動くもの」を最優先する考え方

**霊夢**: 問題文を読んだら、いきなり焼きなまし？

**魔理沙**: **違う。** 灰色帯の鉄則は **「まず動くもの」** だ。順番はこう。

```
1. スコア計算（出力が読める）
2. 合法解を1つ出す（ランダム / 固定 / 超単純貪欲）
3. ローカルで点数を確認
4. あとから改善（貪欲 → 山登り → SA ...）
```

**霊夢**: 最適解を考えるのは後？

**魔理沙**: 後でいい。AHC では**未提出より低スコア提出**の方がマシだ。動かない完璧なアルゴリズムより、**動くダメ解**が先だぜ。

| 段階 | 目的 | 例 |
|------|------|-----|
| MVP | パイプライン確認 | 毎日タイプ1を出力 |
| v0 | 合法 + ちょっとマシ | その日 s が最大のタイプ |
| v1 | スコア改善 | 貪欲 / 山登り |
| v2 | 本番級 | SA / ビームサーチ |

```python
# python/ch02/sample_solver.py — MVP の典型
def main() -> None:
    d = read_problem()
    for _ in range(d):
        print(1)  # とにかく合法出力
```

```python
# 改善版 v0（第5章で本格化）— その日一番 gain が大きいタイプ
def greedy_day(problem, day):
    row = problem.gain[day]
    return row.index(max(row)) + 1  # 1-indexed
```

**霊夢**: スコア計算が先なのは、第1章でやったからもうわかるわ。

**魔理沙**: その通り。第3章ではスコア計算を**モジュールとして整理**する。解法とスコアを分離すると、後の改善が楽になるんだ。

## 3.3 状態（State）と操作（Move）のモデリング

**霊夢**: State と Move って何？

**魔理沙**: ヒューリスティック問題を**プログラムの言葉**に翻訳するための箱だ。

| 用語 | 意味 | Intro HC 問題A の例 |
|------|------|---------------------|
| **State** | 今の解 | 365日分のタイプ列 `[1, 17, 13, ...]` |
| **Move** | 解を少し変える操作 | 「15日目をタイプ3に変える」 |
| **Score** | 解の良さ | 最終満足度 S、contest score |

**霊夢**: Move は1日だけ変える感じ？

**魔理沙**: 基本はそう。**近傍（Neighborhood）** と呼ぶ。焼きなましや山登りは、この Move を繰り返してスコアを見る。

```python
# python/ch03/toy_score.py — 最小モデル（3日・3択）
from dataclasses import dataclass
from typing import List


@dataclass
class ToyState:
    picked: List[bool]  # 各日 pick するか


@dataclass
class ToyInput:
    values: List[int]


def apply_move(state: ToyState, index: int, pick: bool) -> ToyState:
    nxt = ToyState(list(state.picked))
    nxt.picked[index] = pick
    return nxt


def score(state: ToyState, inp: ToyInput) -> int:
    return sum(v for v, p in zip(inp.values, state.picked) if p)
```

## 3.4 スコア関数の実装パターン

**霊夢**: スコア関数、毎回一から書くの？

**魔理沙**: パターンに分けられる。**3層**にすると整理しやすい。

```
[read]  入力 → ProblemInput (+ ScheduleState)
[score] (ProblemInput, ScheduleState) → ScoreResult
[main]  stdin/stdout ラッパー
```

### パターン1: 総当たりシミュレーション

Intro HC の満足度更新はこれ。Day 1 から順に状態を更新する。

```python
# python/ch03/score_module.py — score_schedule（抜粋）
def score_schedule(problem: ProblemInput, state: ScheduleState) -> ScoreResult:
    last = [0] * 26
    satisfaction = 0
    daily = []

    for day in range(1, problem.days + 1):
        t = state.types[day - 1] - 1
        satisfaction += problem.gain[day - 1][t]
        last[t] = day
        decay = sum(problem.decay[i] * (day - last[i]) for i in range(26))
        satisfaction -= decay
        daily.append(satisfaction)

    final = daily[-1] if daily else 0
    return ScoreResult(
        daily=daily,
        final_satisfaction=final,
        contest_score=max(10**6 + final, 0),
    )
```

```go
// go/ch03/score_module.go — 同じロジック
func scoreSchedule(problem ProblemInput, state ScheduleState) ScoreResult {
    last := make([]int, 26)
    satisfaction := 0
    daily := make([]int, 0, problem.Days)
    for day := 1; day <= problem.Days; day++ {
        t := state.Types[day-1] - 1
        satisfaction += problem.Gain[day-1][t]
        last[t] = day
        decay := 0
        for i := 0; i < 26; i++ {
            decay += problem.Decay[i] * (day - last[i])
        }
        satisfaction -= decay
        daily = append(daily, satisfaction)
    }
    // ...
}
```

### パターン3: 合法判定 + スコア

出力が制約を満たすか先にチェックする。

```python
def validate_schedule(state: ScheduleState, num_types: int = 26) -> bool:
    return all(1 <= t <= num_types for t in state.types)


def score_if_valid(problem, state):
    if not validate_schedule(state):
        raise ValueError("illegal schedule")
    return score_schedule(problem, state)
```

```go
func validateSchedule(state ScheduleState, numTypes int) bool {
    for _, t := range state.Types {
        if t < 1 || t > numTypes {
            return false
        }
    }
    return true
}
```
